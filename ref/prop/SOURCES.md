## 选图口径（四条，按优先级）

照 `ref/veh/SOURCES.md` 那套，但第 ① 条是**一票否决**：

1. **绝对不能有水印**。图生3D 会把水印当成物体表面的图案**烘进贴图**，
   而模型建好之后**不会再走一遍去水印**，错就错到底。
   本项目现成的"去水印"实现（`prep_char.py`）只是裁掉画面右下角那一条，
   对**压在主体检上**的图库水印完全无效 → 只能换图。
   **本轮实测复核过一次**：`prop_rock_b` 的首选是 vecteezy 的
   `moss-covered-boulder-…-large_2x`（3497×1960，剪影最好），
   放大到 1:1 一看，岩石正中压着 vecteezy 的 V 标与站名 → **否掉**，改用 freepik 那张。
2. **白底或纯色底**，且背景连通到画面四边（`cut_bg.py` 的灌水靠这个）。
3. **物体完整、单主体**，不与其他物件粘连 —— 3/4 视或侧视，能同时读到顶面与侧面。
4. **分辨率 ≥ 1000 px 长边**（两张岩石/树是 2000 级，灌木 1060）。
   生成侧还会缩到 1024 级，低于这个数就是白给。

**"freepik premium 预览图带水印"这条常识在本轮没成立。**
12 张候选里有 9 张来自 `img.freepik.com/premium-photo/...`，
按经验应当全是水印图，实测**放大到 1:1 全部是干净的**。
判断方式不是"看小图"也不是"看来源站"：把候选拼成对照表先粗筛，
再对中选的那张做**高通增强**（`|原图 − 高斯模糊| × 7`）逼水印 ——
低对比度的文字/logo 在这一步会浮出来，而岩石纹理与叶簇只是散斑
（两张岩石、树、灌木的高通图见 `sweep/prop_ref/_wmk.png`）。

## 抠底与补方（本轮实际用的命令）

```bash
PY=C:/Users/<user>/.workbuddy/binaries/python/envs/default/Scripts/python.exe

$PY tools/cut_bg.py sweep/prop_ref/pick/raw_prop_rock_a.jpg assets/art/prop/prop_rock_a.png \
    --thresh 232 --square --side 1024 --erase 1700,1640,2000,1840
$PY tools/cut_bg.py sweep/prop_ref/pick/raw_prop_rock_b.jpg assets/art/prop/prop_rock_b.png \
    --thresh 232 --square --side 1024
$PY tools/cut_bg.py sweep/prop_ref/pick/raw_prop_pine.jpg   assets/art/prop/prop_pine.png \
    --thresh 244 --square --side 1024 --erase 480,1852,1470,1995
$PY tools/cut_bg.py sweep/prop_ref/pick/raw_prop_bush.jpg   assets/art/prop/prop_bush.png \
    --thresh 244 --square --side 1024
```

两处 `--erase` 各有各的理由，都不是随手加的：

- **松树**：原图树干底部有一块**深褐色土盘**（约 2.2 m 宽，落在原图 y 1852~1995、
  x 586~1394）。它是"暗"的，所以亮度阈值把它算成物体 —— 阈值治不掉，
  留着就被烘成树干底下的一块平板。定点擦掉之后树干在土盘上沿收口，
  正面看就是"树从地面长出来"。
- **岩石 A**：原图的**软投影向右伸出一块楔形**（原图 y 1690~1820、x 1700~2000）。
  这块投影严格在岩石剪影之外（y=1740 那一行岩体最右到 x=1704），所以擦掉它
  不会啃到岩石本身；留着则会被烘成一块贴地的板。
- **岩石 B 的影晕没擦**：它的投影是**贴着剪影底缘的一圈**（阈值 150 与 205 的
  边界几乎重合），擦它必然要啃掉岩石底缘那几行。而这块石头在场上**底沉 0.24·r**，
  那一圈本来就在地面以下 —— 值得留在原图里，不值得为它动刀。

**⚠ 亮度阈值分不开"投影"和"岩面"**：岩石 A 的投影亮度 p25=174 / 中位 234，
而岩面本身 p75=153 / 最大 255 —— 两个区间重叠。所以判据不是"设一个阈值把投影筛掉"，
而是"**阈值取在投影的最暗端之上、再对越界的形状定点擦**"。
量法：逐行统计 `lum<150`（岩体核心）与 `lum<205`（含浅投影）的 x 区间，
两者**开始分叉的那一行**就是岩体底缘，投影在它之外。

## 为什么是这四个

用户 2026-09-22 的裁决是**地物四件套**（在"树专项 / 小件专项 / 阵地工事"之间选的），
判据是「占屏面积 × 现在有多塑料 × 风险」：

| 键 | 现在是什么 | 为什么先换它 |
|---|---|---|
| `prop_rock_a` / `prop_rock_b` | `make_rock_mesh` 的"极坐标球 + 半径扰动"多面体 | **每关三十来块**，占屏面积最大；两个剪影是为了不出现"同一块石头复制三十遍" |
| `prop_pine` | 圆柱树干 + 斜插分枝 + **4~6 个绿球簇**树冠 | **每关二十来棵**，中景最出戏的一处（"一根杆顶三个球"） |
| `prop_bush` | 3~5 个小球 | **每关十几丛**，近景里读得出是光滑球 |

**没有**换 `Wall`（桥墩石墙）/ `Trench`（战壕）/ `Barrel`（油桶）：那是"小件专项"，
数量少、单件占屏小，性价比排在四件地物之后。**也没有**新增 PropType
（沙袋 / 铁丝网 / 拒马那类阵地工事）：那要动逻辑层的布点，
会改变战役关卡的掩体布局与旧基线，不是纯表现层改动。

## 引擎里的归一化口径（2026-09-22）

**这一档换的是"长什么样"，不是"占多大地方"** —— 逻辑层的 `p.r` 是掩体半径，
它决定这块东西遮住多大一片，所以模型必须被拉到"原来那套图元的包围盒"：

```
岩石   宽 = 2·r        高 = 1.00·r     底沉 0.24·r   （r = p.r × S，S = 0.05）
灌木   宽 = 2.2·r      高 = 0.80·r     底沉 0.10·r
松树   高 = 7.0 + rng·3.0（沿用原公式），冠幅跟着模型走
```

两款"按宽"、一款"按高"的理由、以及"树冠因此比原来宽（约 2.1 m → 约 4 m）"
这条代价，写在 `src/node/scene_builder.cpp` 的 `kPropArt` 长注释里。

变体策略：两份岩石剪影按 `hash(p.x, p.y)` 交替，偏航也按 hash 撒开。
生成额度是有限的（内置通道 5 次/天、约 40 积分/个），
"多做几个变体"太贵，"一份模型 + hash 轮换"是同样效果里最便宜的。

## 结果：四张里**只采用了两张**（2026-09-22）

四张参考图**都成功生成了模型** —— 四个任务全报 `DONE`、各 40 积分、各 50,000 三角面、
成品 1.20~1.55 MB。差别只在几何，而几何这一项让后两件**不能用**：

| 键 | 成品 | 世界包围盒 (X, Y, Z) | 结论 |
|---|---|---|---|
| `prop_rock_a` | 1.20 MB | (0.780, 0.891, 0.788) | **采用** |
| `prop_rock_b` | 1.29 MB | (1.003, 0.355, 1.118) | **采用** |
| `prop_pine` | 1.28 MB | (0.070, 1.196, 0.075) | 弃用：**一根杆**，水平只有高的 6.3% |
| `prop_bush` | 1.48 MB | (1.002, 0.0016, 0.988) | 弃用：**一张水平圆盘**，高只有最大维的 0.16% |

**三组独立测量互相印证**（引擎世界包围盒 / 瘦身前的 `raw.glb` 顶点包围盒 /
服务端自己的 `PreviewImageUrl` —— 后者是张 512×512 却只有 2026 字节的近空白 PNG），
所以不是下载或瘦身环节弄坏的。**根因：这一档通道重建不出"半透明叶簇围成的体积"** ——
参考图里枝干之间透出背景，于是要么只剩一根主干（树），要么把地面剪影当成物体（灌丛）。
两块**不透明实体**（岩石）成功、两件半透明叶簇失败，这个对照很干净。

两个退化成品已移到 `sweep/gen3d_prop/rejected/`（原地保留会让仓库白背 2.8 MB，
且日后放宽判据时它们会静默复活）。代码侧新增了**按比例**的退化判据拦这一类，
详见 `README.md` 的「地物形象」一节。

## 树与灌丛：**没有**走"复做配方"，改走了文生3D（2026-09-23）

上面那条"下一次复做的口径"（换不透明的参考图 + 换同族档位）**最终没有执行**。
原因：重新想了一遍根因 —— 失败的根源不是"这张图不够不透明"，而是**通道本身是单视图重建**。
只要输入还是一张照片，就还是"反推一个看不见的体积"。所以这一轮换的是**输入通道**：

```
echo -n "<token>" | python tools/gen3d.py --text "<中文描述>" <结果json> --enable-pbr --face-count 50000
```

两个模型不再需要参考图，`assets/art/prop/prop_pine.png` / `prop_bush.png` 因此**没有参与生成**
（留着只是为了日后走多视图通道时当输入）。

| 键 | 上一轮（图生3D） | 这一轮（文生3D） | 成品 |
|---|---|---|---|
| `prop_pine` | 水平只有高的 6.3%（一根杆） | 冠幅/高 **0.589** ✅ | 1.45 MB / 5 万面 |
| `prop_bush` | 高只有最大维的 0.16%（一张饼） | 最小维 ≥ 2% ✅ | 1.27 MB / 5 万面 |

prompt 是照**根因**写的，四条要点（原文见 `tools/gen3d_batch.py` 的 `PROFILES["prop"]["prompts"]`）：

1. 点明 **"完全看不到枝干之间的空隙 / 不透光"** —— 直接对着上一轮失败的那件事写；
2. 点明形体是**完整饱满的圆锥**（给重建一个明确的体量先验，而不是"一丛枝叶"）；
3. 写 **"写实摄影 / 纯白背景 / 只拍这一棵"**，避免生成卡通风或带场景的图（我们只要单体）；
4. 灌丛额外点明 **"高度约为宽度的一半"**，与引擎侧 `hw=0.36` 的口径一致。

**这个方向值得记下来**：以后遇到"靠半透明结构表达体积"的东西（树冠、灌木丛、草丛、
火焰、烟），不要再花时间找"更不透明的照片"，直接换文生3D。

### 这一轮意外踩到、也修掉的：下载判据用了"文件在不在"

`gen3d_batch.py` 原来的下载判据是 `if not os.path.exists(raw_glb)`。而 raw 是**按 key 命名**的：
上一轮遗留的 `prop_pine.raw.glb` 让这一轮的下载被整个跳过 → 刚花 40 积分换来的新模型被丢掉、
改用旧 raw 重新瘦身，**成品与上一轮逐字节相同（md5 一致）**，而日志写的是
"生成完成 / 积分 40 / 齐备 2/2 / EXIT=0" —— 从外面完全看不出异常。
唯一能看出的线索是 **raw 的 mtime 还停在上一轮**。

两个新模型最后是靠结果 JSON 里的签名 URL **抢救回来**的（额度已经花了，结果一直在服务端）。
修法：把判据改成"**这一轮有没有真提交过**"（`done_json` 为假就先删同名 raw）；
下载失败时也把"URL 在哪个文件里、可手工重下"写进日志。

**教训**：`dst_glb` 那侧的同类问题（"光任务成功不算完成，成品规格也是完成度"）此前已经补过，
但那次补的是**成品**、漏了**原料** —— 两条判据长得像，检查的却是两个文件。

`v1`（上一轮 09-23 的现役件，108 字）留作基准：

### 裁决依据：半径-高度剖面的锯齿度（**不靠眼睛**）

40 层，每层取点到中轴的最大水平距离 r_i，按 r_max 归一化：

| 件 | 锯齿度 zigzag | 起伏 flips | 单调占比 |
|---|---|---|---|
| `prop_rock_a`（光顺裸岩，参照） | 0.0038 | 4 | 0.69 |
| `prop_bush`（灌丛，参照） | 0.0104 | 1 | 0.51 |
| 09-22 塌成杆的树（参照） | 0.0105 | 5 | 0.92 |
| **`v1` / `v2`（"一摞飞盘"）** | **0.2120 / 0.2035** | 18 | 0.62 / 0.64 |
| `v3`（采用） | **0.0268** | 10 | 0.74 |

人眼读作"一摞飞盘"的那两件，指标比所有光顺件高 **20~55 倍**；两条参照曲线的形状也自证：
`v1` 的半径在 ~1.0 与 ~0.1 之间反复砸（满半径薄盘 + 盘间几乎空、只剩细树干），
`v3` 从 1.00 平滑单调收到 0.07。

### 结论（可复用）

**文生3D 的 prompt 里，"不要 X" 基本不起作用。** `v2` 把要避开的形状逐条否定了一遍，
指标几乎不动。起作用的是**换掉描述里的主语**：
旧主语是"**针叶枝条**"（让生成器去建"枝条"这个实体，它最省面的解法就是叠起来的圆盘），
新主语是"**密实饱满的圆锥体 / 绒团**"（按"一团密实的体积"去补面）。
"完全不透光"这句从头到尾都在，它不是决定项。

## 树干是品红色：一次"重做 **输给** 离线改贴图"的裁决（2026-09-24）

上一轮把树冠修好了，却漏掉一件更显眼的东西：**树干是一整面品红**。
出生点就在树底下，第一人称一抬头就是它。它从 09-23 起就在，
只是因为上一轮的判据**只判形状**（锯齿度），而"颜色错"不在那几条判据的值域里。

### 根因：两层，第二层是这一轮才挖出来的

1. 生成器给的 `baseColorTexture` **底色本身就是暗红** —— 导出来看过：红底 + 灰绿枝叶团块，
   像一块迷彩。所以不是引擎、不是 tint。
2. **`v1` / `v2` / `v3` 三个 prompt 里都明写着"红褐色树干"**，末尾还都写着"东北**红**松"。
   生成器只是忠实执行了描述 —— 这不是抽风，是**描述里真的带着色相指令**。

（`v3` 那句"笔直的红褐色树干"是从 `v1` 逐字继承下来的 —— 上一轮做"措辞手术"时
只动了树冠那半句，颜色描述这一半**从来没人过问**。这是"局部修改"的典型盲区：
你盯着要改的那句，就不会去看旁边那半句。）

### 两条路并行，各出一件

| 代号 | 做法 | 代价 |
|---|---|---|
| `v4` | 重新文生3D（**形状措辞逐字保留 v3**，只做颜色手术） | 1 次额度 / 40 积分 |

`v4` 的 prompt 全文（180 字；改动处加粗）：

> 一棵高大的针叶松树单体，笔直粗壮的树干，**树皮是粗糙纵裂的木质，深灰褐色混着青灰与土黄、颜色灰暗朴素不鲜艳**，树冠是一个密实饱满的圆锥体，通体被极细的针叶紧密覆盖，质感蓬松浓密得如同一个绿色的绒团，枝条完全被针叶包裹住、看不出分层也看不出任何间隙，整体轮廓连续光滑、从底部到顶端均匀收尖、没有横向伸出的枝盘，朝鲜战场山地常见的**松树**，写实摄影，纯白背景，只拍这一棵树

（"朝鲜战场山地常见的东北红松" → "…常见的松树" —— **"红"这个字本身也是色相线索**。）

### 结果：重新生成**输了**

| 候选 | 贴图红系 | 锯齿度 | 几何 | 树干观感 |
|---|---|---|---|---|
| `v3`（现役） | 8.7% | 0.0268 | 基准 | 一整面品红 |
| `v4`（花额度） | **0.0%** | 0.0275 | 合格，但与 v3 不同（重掷了骰子） | **灰白** —— 读作水泥柱 ❌ |
| `g_B`（零额度，**采用**） | **0.1%** | **0.0268** | **逐位不变** | **深棕树皮** ✅ |

### 两条可复用的结论

1. **"重新生成"会把已经验收过的几何一起赔进去。** `v4` 的形状措辞与 `v3` 逐字相同，
   但生成是**掷骰子** —— 出来的树冠形态与 `v3` 不同（锯齿度 0.0275 vs 0.0268，
   只是"两次都合格"）。而离线改贴图**几何判据逐位不变**。所以：
   **只坏颜色时，先想"能不能只动像素"。**
2. **"保留明度"会让树皮读作水泥柱。** 离线改的第一版（保 V、饱和 ×0.55）红系已经归零，
   但画面里树干是**浅灰**的 —— 同一 V 下红→黄褐的**感知亮度是上升的**，再叠上降饱和
   （接近灰），受光面直接发白。修法是明度也按比例压（`--lift 0.78`）。
   **判据归零 ≠ 观感到位**，两个都得看。
