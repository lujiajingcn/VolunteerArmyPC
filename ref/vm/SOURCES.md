## 选图口径（五条，按优先级）

照着 **`ref/veh/SOURCES.md`** 那套，但第 ① 条在这里被提到了最前面，而且比载具更硬：

1. **绝对不能有水印** —— 这是**一票否决项**，不是"可以忍"的缺点。
   图生3D 会把水印当成本体上的图案**烘进贴图**，而模型建好之后**不会再走一遍去水印**，
   错就错到底（技能第 0 步 / 铁律 2）。本项目现成的"去水印"实现
   （`prep_art.py` / `prep_char.py`）**只是裁掉画面右下角那一条**，
   对**压在主体上**的图库水印完全无效 —— 所以压在手上的水印只能**换图**，不能修。
   实测：Bing 上"戴手套 + 握拳"的图几乎全是 alamy / dreamstime / freepik premium，
   **个个带水印且压在主体上**（候选表见 `sweep/vm_ref/_sheet_hand_r2.png` / `_sheet_glove2.png`）。
   → 于是把条件放宽成"**戴不戴手套都行、只要是干净的握拳**"，因为手套的观感可以在引擎里
   用一个色调乘数补（见下"形态与贴图的分工"）。
2. **姿势必须是握持性的**：手指弯曲、能读成"攥着东西"。
   张着手指的手放到握把上会当场露馅（指头伸在枪身外面），而**手指是生成不出来的**——
   图生3D 只还原输入的形状，不会替你把手弯起来。
3. **单手主体**（不是一双）。一双会生成"两只手连在一起"的一坨。
4. **单色 / 浅色背景**，且背景**连通到画面四边**（抠底靠这个）。
5. 长宽比不极端（补方之后主体还能占满画布）。

## 抠底这一步本轮的额外教训（这张图不能直接喂 cut_bg.py）

`tools/cut_bg.py` 的判据是**亮度阈值 + 从四边灌水**，它假设"**背景亮、物体暗**"
（那个假设是给 DP-27 摆在石地板、带投影那张定的）。本轮这张的失败方式完全反着来：

- 背景是**浅色墙面（226~230）+ 手投在墙上的暗影（<60）**，
  而手本身是中间调（32~219）—— **暗影比手还暗**，
  于是"亮度低"这个判据同时命中"暗影"和"手"，分不开。
- 实测：`--thresh` 从 222 一路提到 246，**遗留的那块暗影一个像素都没少**
  （因为它始终落在"物体"一侧）。刷白条件从 `lum>168` 放到 `lum>100` 也无效
  （那块暗影 `lum<60`）。

**有效的判据是"饱和度 + 从边缘连通"**：墙面（含暗影）是**中性灰**（`sat≈3`），
手是**肤色**（`sat` 中位 65）—— 两个世界。于是：

```
背景候选 = sat < 26            # 亮墙与暗影一起命中
再从画面四边洪泛（4-邻域）      # 只吃"连通到边缘"的那一块
```

洪泛这一步是**必须的**、不能只按饱和度一刀切：手内部也有低饱和像素
（高光/反光，实测占手部中心区的 **1%**，`sat` 1% 分位 = 2），
只按阈值刷会把它们挖成洞；**而洪泛只吃连通到边缘的那一片，手内部的高光留得住**。

实测效果：暗影残留从"一块 20×25 px 的灰斑"缩到**几个孤立小点**（各 3~5 px），
已被判定为可接受（图生3D 会忽略它）。

## 形态与贴图的分工（本轮的核心取舍）

选的是**空手握拳**（皮肤），而不是"戴手套的手"——这是**刻意**的：

- **形状**只能来自参考图，而干净（无水印）的握拳图只有空手 → 形状取它；
- **颜色/质感**在引擎里补：真模型自带贴图（皮肤），
  给它一个**色调乘数**（albedo tint）就变成手套的皮革色，
  皮肤贴图里的褶皱/指节起伏会**原样保留**成手套上的细节。
  这比"用纯色材质整体覆盖"好 —— 后者会把贴图细节全丢掉。

皮肤 ≈ `RGB(230,180,160)`，乘 `(0.50, 0.42, 0.36)` ≈ `RGB(115,76,58)`，
与现有程序化手套实测渲染色 `RGB(119,90,83)` 同一档。

**为什么不干脆保留程序化手套的纯色 albedo**：程序化那套是"方块 + 纯色"，
本来就没有贴图细节可丢；换成真模型后**有**细节可保留，所以用乘数而不是覆盖。

## 接入之后的实测结论（2026-09-21）

**① 左手不单独生成，这条决定成立。** 左手借用右手的 `.glb` + 左右镜像，
用各自的识别色掩码在常规图上取亮度做 A/B（`VA_VM_HAND_NOMIRROR=1` 对照）：

| | 手套（远/支撑） | 手套（近/扳机） | 袖子 |
|---|---|---|---|
| 镜像 | n=12898 中位 L=36 | n=73319 L=80 | n=31213 L=42 |
| 不镜像 | n=15210 中位 L=40 | n=74950 L=81 | n=31201 L=42 |

**两边几乎逐位相同** → 负缩放没有把法线/绕序弄坏（手模材质一律 `CULL_DISABLED`，
见 `adopt_hand_subtree`）。省下一张生成额度。

**② 这条长轴的真实语义 = "腕横纹 → 指节"**。模型是"握拳 + 一截腕柱"，长轴长度含那截
手腕。所以归一化按 **0.115 m**，不是"腕→中指尖 18.5 cm"（按后者会整体放大 1.6 倍）。
扫档记录（0.185/0.145/0.135/**0.115**/0.095）与取证图在 `sweep/vmhand_hip*/`（已 gitignore）。

**③ 朝向角 `4.1°,20.2°,48.5°` 是解出来的**，不是扫出来的：约束是"腕端（模型 −Y）指向肘、
手背（模型 +Z）指向相机"，联立解欧拉角、回代误差 2.2e-16。
另一组解 `(−31.0,−20.7,39.6)` 会让腕口切面正对相机（画面里出现一个大圆盘）。

**④ 这个模型还有一个"参考图看不出来"的性质**：腕口是**开口**的（没封盖），
所以朝向必须保证那个切面朝向肘/画面外 —— 转正对相机时不是"少了点东西"，
而是出现一块大平板。开镜时它还会露出来（开镜让位那套姿态同时把它挡住了）。
